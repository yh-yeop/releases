## 구조

| 무엇 | 어디 | 누가 고치나 |
|---|---|---|
| 앱 목록 (정본) | `apps.json` | 사람 — 앱을 추가할 때 한 줄 |
| 버전 릴리스 `<앱>-v<버전>` | GitHub Releases | 각 앱의 배포 스크립트 또는 손 |
| 앱별 최신 정보 `manifest.json` · `manifest-pre.json` | 고정 릴리스 `<앱>-latest` 의 첨부 파일 | **자동** (`tools/sync.mjs`) |
| 전체 요약 `index.json`, manifest 사본 | Pages `https://yh-yeop.github.io/releases/` | **자동** |
| 위 다운로드 표 | `README.md` 의 `apps:start ~ apps:end` | **자동** |

릴리스를 올리거나 고치거나 지우면 GitHub Actions(`.github/workflows/sync.yml`)가 `node tools/sync.mjs` 로 나머지를 전부 맞추고,
규칙 위반은 실행 결과 요약(Actions → sync)에 경고로 남긴다. `apps.json` · `tools/` 를 고쳐 푸시해도 돈다.
(릴리스 이벤트는 태그를 가리켜 Pages 배포가 막히므로, 그때는 같은 워크플로를 main 에서 다시 실행시키는 `relay` 단계를 거친다.
옛 태그 — 이 워크플로가 생기기 전 커밋에 달린 것 — 의 릴리스를 고치면 이벤트로는 돌지 않으므로 매시간 예약 실행이 따라잡는다.) 손으로 돌릴 수도 있다:

```
node tools/sync.mjs                 # 무엇이 바뀔지 미리 보기 + 규칙 검사 (gh CLI 로그인 필요)
node tools/sync.mjs --write         # manifest 올리기
node --test tools/*.test.mjs        # 규칙 함수 테스트
```

### 새 앱 추가

1. `apps.json` 에 항목 추가 (아래 표) → 푸시
2. 첫 버전 릴리스를 아래 배포 규칙대로 올린다
3. 끝. manifest · `<앱>-latest` · 다운로드 표 · 소개 사이트 카드가 자동으로 생긴다.
   소개 사이트에서 더 꾸미려면(서브페이지, 배너, 특징 줄) `yh-yeop.github.io` 의 `js/data.js` 에 `id` 가 `site` 와 같은 항목을 둔다 (그쪽이 우선)

| `apps.json` 필드 | 필수 | 뜻 |
|---|---|---|
| `id` | ✔ | 태그 접두사 (`<id>-v1.0.0`). 앱마다 달라야 하고 바꾸지 않는다 |
| `name` | ✔ | 표시 이름. 릴리스 제목이 `<name> <버전>` 이어야 한다 |
| `desc` | | 한 줄 설명 (다운로드 표 · 사이트 카드) |
| `platforms` | | `windows` · `android`. 여기 없는 플랫폼 파일을 올리면 경고 |
| `category` | | 사이트 분류 (기본 `app`). 쓸 수 있는 값은 소개 사이트 `js/data.js` 의 `CATS` (지금 `maple` · `minecraft` · `web` · `app` · `game` · `etc`). 모르는 값이면 사이트가 `app` 으로 보여 준다 |
| `beta` | | `true` 면 프리릴리스(베타)도 최신으로 보여 준다 |
| `site` | | 소개 사이트 id (`#p/<site>`). 사이트 카드 · 소개 링크에 쓴다 |
| `page` | | 소개 페이지 주소 (없으면 `https://yh-yeop.github.io/#p/<site>`) |
| `icon` | | 이 저장소의 `icons/` 안 경로 또는 `https://` 주소 — 사이트 카드 아이콘 |
| `points` · `tags` | | 사이트 카드의 특징 줄 · 태그 |

## 배포 규칙

- 태그는 반드시 `<앱>-v<버전>` (예: `YTDL-v1.2.0`, `Fracture-v0.9.0-beta`). 버전은 semver — 숫자에 앞자리 0을 붙이지 않는다 (`0.9.01` ✗ → `0.9.1`)
- 릴리스 제목은 `<표시 이름> <버전>` (예: `MP3 Checker 2.3.7`, 베타는 `Fracture 0.9.0 베타`, `0.9.1-beta.2` → `Fracture 0.9.1 베타 2`). 앱은 제목을 보지 않는다
- 베타는 버전에 `-beta`(또는 `-beta.N`)를 붙이고 **프리릴리스**로 올린다. 정식은 꼬리표 없이 정식 릴리스로
- Windows 설치 파일은 이름에 `Setup` 이 든 `.exe` (`<앱>-Setup-<버전>.exe`), 설치 프로그램이 없는 앱은 `<앱>-<버전>-win64.zip`. Android 는 `<앱>-<버전>.apk`
- Minecraft 모드팩은 `<앱>-<버전>.mrpack` (플랫폼 `minecraft`). 같은 릴리스에 서버용 `.jar` · 전시장 월드 · Prism 인스턴스 `.zip` 을 더 올려도 되고, 설치 파일로 치는 것은 `.mrpack` 하나다 (산업크래프트, `yh-yeop/sanupcraft` 의 `tools/publish_release.py` 가 올린다)
- 설치 파일마다 `<파일>.sha256` (`<hex>  <파일 이름>`)을 함께 첨부
- 최신은 **게시 순서가 아니라 가장 높은 버전**이다. 옛 버전 수정판을 나중에 올려도 최신이 바뀌지 않는다. 릴리스를 지우거나 드래프트로 돌리면 그다음 버전으로 내려간다
- 저장소 전체의 "Latest" 는 마지막으로 올린 앱의 릴리스를 가리키므로 아무것도 여기에 의존하지 않는다

## manifest.json 규약 (schema 1)

앱이 릴리스 목록을 훑지 않고 자기 최신 버전을 알기 위한 파일. 같은 내용을 두 곳에서 받을 수 있다:

```
https://github.com/yh-yeop/releases/releases/download/<앱>-latest/manifest.json       정식 최신
https://github.com/yh-yeop/releases/releases/download/<앱>-latest/manifest-pre.json   프리릴리스(베타) 최신 — 베타가 있는 앱만
https://yh-yeop.github.io/releases/apps/<앱>/manifest.json                             위 사본 (Pages, CORS 허용 → 브라우저·웹뷰용)
https://yh-yeop.github.io/releases/apps/<앱>/manifest-pre.json
```

```json
{
  "schema": 1,
  "app": "YTDL",
  "version": "1.5.2",
  "tag": "YTDL-v1.5.2",
  "prerelease": false,
  "published_at": "2026-10-20T10:04:25Z",
  "release_url": "https://github.com/yh-yeop/releases/releases/tag/YTDL-v1.5.2",
  "notes": "릴리스 본문 (Markdown)",
  "assets": {
    "windows": { "name": "YTDL-Setup-1.5.2.exe", "url": "https://github.com/…/YTDL-Setup-1.5.2.exe", "size": 78084578, "sha256": "4002aa…" },
    "android": { "name": "…apk", "url": "…", "size": 0, "sha256": "…" }
  }
}
```

| 필드 | 뜻 |
|---|---|
| `schema` | 형식 버전. 필드를 빼거나 뜻을 바꿀 때만 올린다 (추가는 그대로 1) |
| `version` | `tag` 에서 `<앱>-v` 를 뗀 semver |
| `assets` | 플랫폼 키(`windows`: `Setup` 이 든 `.exe`, 없으면 `win64` 압축본 `.zip` / `android`: `.apk`) → 그 버전 릴리스의 설치 파일. 해당 플랫폼이 없으면 키가 없다. 압축본인지는 `name` 의 확장자로 안다 |
| `sha256` | GitHub 가 계산한 자산 digest. 없으면 `null` |

만드는 쪽:

- 정본은 `tools/sync.mjs` (Actions). 앱마다 최고 버전 정식 릴리스 → `manifest.json`, 최고 버전 프리릴리스 → `manifest-pre.json` 으로 맞추고, 내용이 같으면 건드리지 않는다
- YTDL·MP3Checker `release.ps1`, Tododoo `scripts/release.mjs` 도 게시 직후 같은 형식으로 올린다 (Actions 를 기다리지 않고 바로 반영). 형식이 어긋나면 Actions 가 다시 덮어쓴다
- 올릴 때는 `<파일>.new` 로 올린 뒤 옛 파일을 지우고 이름을 바꾼다 → 파일이 없는 순간이 아주 짧다

읽는 쪽 (앱 업데이터):

- 정식 채널은 `manifest.json`, 베타 채널은 `manifest.json` 과 `manifest-pre.json` 을 둘 다 읽어 **더 높은 버전**을 쓴다 (베타 중에 정식이 나오면 정식으로)
- 받지 못하거나 형식이 틀리면 릴리스 목록(`<앱>-v` 접두사)으로 넘어간다
- 브라우저·웹뷰는 `github.com/…/download/` 주소가 CORS 로 막히므로 Pages 사본을 쓴다

## index.json (Pages)

`https://yh-yeop.github.io/releases/index.json` — 모든 앱의 최신 정보 요약. 소개 사이트가 이것 하나로 카드와 다운로드 버튼을 만든다 (GitHub API 횟수 제한 없음).

```json
{
  "schema": 1, "generated_at": "…", "repo": "yh-yeop/releases",
  "apps": [{
    "id": "Fracture", "name": "Fracture", "site": "fracture", "category": "game", "desc": "…", "platforms": ["windows"], "beta": true,
    "page": "https://yh-yeop.github.io/p/fracture/", "icon": null, "list_url": "…", "manifest": "…/apps/Fracture/manifest.json",
    "stable": null,
    "pre": { "version": "0.9.0-beta", "tag": "…", "name": "Fracture 0.9.0 베타", "prerelease": true, "published_at": "…", "release_url": "…",
             "assets": { "windows": { "name": "…", "url": "…", "size": 0, "sha256": "…", "kind": "zip" } } }
  }]
}
```

- `stable` = 최고 버전 정식 릴리스, `pre` = 그보다 높은 프리릴리스가 있을 때만. 없으면 `null`
- `assets.*.kind` = `installer` · `zip` · `apk`. 릴리스 노트(`notes`)는 크기 때문에 빼고 manifest 에만 둔다
